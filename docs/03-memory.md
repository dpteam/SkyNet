# Память: как DOS перестаёт быть 64-килобайтным

Статус: M1, EMS работает и проверен на DOSBox. XMS и DPMI — только
детекция, с объяснением почему.

## Проблема в одном числе

В 16-битном DOS `size_t` — 16 бит. Значит **один `malloc()` не может
превысить 64 КБ**, и не потому что «DOS жадный», а потому что размер
физически не влезает в аргумент.

Проверено на реальном DOS:

```
[sky] arena: 65280 of 8388608 bytes granted
```

Попросили 8 МБ, получили 65 280 байт. Модель Tiny-2.1 — это 380 КБ
весов. То есть **на DOS модели негде жить**, и никакая оптимизация
алгоритма этого не меняет.

## Решение: EMS 4.0

EMS даёт до 32 МБ, но с жёстким ограничением: память **страничная**,
по 16 КБ, и видна через 64-килобайтное окно в обычной памяти —
одновременно 4 страницы.

```
       ┌──────────────────────────────┐
       │  обычная память (640 КБ)     │
       │   ┌────────────────────────┐ │
       │   │ окно EMS, 64 КБ        │ │  <- сюда видно 4 страницы
       │   │  слот 0: страница N    │ │
       │   │  слот 1: страница M    │ │
       │   │  слот 2: ...           │ │
       │   │  слот 3: ...           │ │
       │   └────────────────────────┘ │
       └──────────────────────────────┘
              ▲ map()
       ┌──────┴───────────────────────┐
       │  EMS: до 2048 страниц по 16К │
       └──────────────────────────────┘
```

API — четыре вызова `INT 67h`:

| Функция | Что делает |
|---|---|
| `AH=40h` | есть ли драйвер |
| `AH=41h` | где окно (сегмент) |
| `AH=43h` | выделить N страниц → handle |
| `AH=44h` | показать страницу в слоте окна |
| `AH=45h` | освободить |

## Главное архитектурное решение

**EMS не притворяется линейной памятью.**

Соблазн очевиден: сделать `void *sk_alloc(n)` поверх EMS и отдавать
указатель. Это работает ровно до второго выделения — потом `map()`
переставит страницу, и первый указатель начнёт молча указывать на чужие
данные. Такой баг не падает, он портит веса, и найти его в году 30
невозможно.

Поэтому два разных инструмента:

| | `sk_arena` | `sk_pool` |
|---|---|---|
| Модель | линейная | страничная |
| Где | conventional / DPMI / OS | EMS |
| Доступ | указатель | `read` / `write` |
| Потолок на DOS | 64 КБ | 32 МБ |
| Для чего | код, состояние, мелкие структуры | веса |

`sk_pool` не отдаёт указателей вообще. Только:

```c
int sk_pool_read (sk_pool *p, sk_u32 off, void *dst, sk_u32 len);
int sk_pool_write(sk_pool *p, sk_u32 off, const void *src, sk_u32 len);
```

Функции сами решают, какую страницу показать, и пересекают границы
страниц внутри одного вызова. Модельный слой читает матрицу весов
построчно — это ровно тот паттерн, под который такой API и сделан.

## Что проверено

Selftest пишет 3 страницы (48 КБ) узором, который вычисляется из смещения
(никакого буфера-источника — на DOS лишние 48 КБ в сегменте данных
негде взять), затем читает обратно кусками по 173 байта. Разные
выравнивания при записи и чтении означают, что **каждая граница страницы
пересекается в двух разных местах** — если `map()` где-то забыт, тест
это увидит.

Плюс проверка, что чтение за концом хранилища возвращает отказ, а не
заворачивается на начало.

## Почему XMS и DPMI только детектируются

Это не лень, а честная оценка стоимости.

**XMS** даёт память выше 1 МБ, но доступ — только копированием через
bounce-буфер в обычной памяти. Для весов это приемлемо, но вызов
драйвера — это **дальний вызов по указателю** `ES:BX`, полученному из
`INT 2Fh AX=4310h`. Чтобы загрузить регистры перед дальним вызовом,
нужна ассемблерная вставка, **своя для каждого компилятора**:
OpenWatcom `#pragma aux`, Turbo C псевдорегистры `__AX`, DJGPP AT&T
синтаксис. Три разных куска ассемблера ради того, что EMS уже даёт.

**DPMI** — самый большой выигрыш: плоское 32-битное адресное
пространство, и тогда `sk_arena` просто работает на мегабайты. Но DPMI
требует перехода в защищённый режим, а это другой режим выполнения всей
программы, не «ещё один бэкенд». Это веха M1b, отдельная работа, и
делать её вслепую без цели (модели ещё нет) — неправильный порядок.

Поэтому в отчёте они видны, но помечены как «detected, not used yet».
Отчёт, который врёт о возможностях, хуже отсутствия отчёта.

## Что это разблокирует

Без EMS: модель обязана быть ≤ 64 КБ. Это ~60 000 параметров int8 —
меньше, чем Tiny-2.1 (367 000).

С EMS: 32 МБ. Tiny-2.1 влезает с запасом в 80 раз, и остаётся место
под несколько экспертов MoE.

Именно поэтому M1 идёт перед M2: писать модель под потолок 64 КБ, чтобы
потом переписывать, — это двойная работа.
