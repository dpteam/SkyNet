# Архитектура SkyNet

Статус: M0 реализован. Документ описывает систему целиком, включая то,
чего ещё нет, чтобы у вех был адрес.

---

## 0. Постановка

Исходное задание — `PROMPT.md`. Оно содержит несколько требований, которые
несовместимы друг с другом, если понимать их буквально. Первый раздел —
что с ними сделано и почему.

### Что держится

**Строка 6 — простые числа.** Это лучшее в задании. Сверхпростые
(`p_n`, где `n` простое) дают детерминированное логическое время, не
зависящее от RTC. Для миссии на 50 лет это критично: часы не дрейфуют,
чекпоинт воспроизводим, рестарт с любого сверхпростого даёт побитово тот
же результат.

**Строка 25 — два модуля одной программы.** Правильно: иначе модель и
обучение разъедутся.

**Tiny-2.1 как база.** Правильно: там уже есть рабочий int8-инференс в
640 КБ и измеримая метрика — 61% на 780 невиданных вопросах. Это baseline,
а не «AGI done».

### Что переписано

| Требование | Реальность | Решение |
|---|---|---|
| «Потоки» в DOS | В реальном режиме потоков нет | Кооперативные шаги с бюджетом памяти; гонок нет по построению |
| «Любое кол-во ОЗУ» | 8088 видит 640 КБ + EMS/XMS | Арена над 5 бэкендами, ни одного `malloc` после загрузки |
| «Компилится через TCC» | 16-бит DOS TCC на машине нет | Профили: Turbo C 2.0 / OpenWatcom / DJGPP / TCC / GCC; ядро strict C89 |
| «Меняется логика каждый цикл» | За 50 лет это самораспад | Мутационная поверхность: только веса, таблицы поведения, блоки `/*EVOLVE*/`. Ядро immutable |
| «Ни разу не отключится» | Невозможно | Теряем не больше одного чекпоинта, всегда восстанавливаемся, состояние никогда не портится |
| «Всё на математике» | `ZMath.cs` — 200 отношений π/Фейгенбаума | Математичность = инварианты + детерминизм, а не количество констант |

Про последнее отдельно: `ZMath.cs` строит ~200 комбинаций π, e, φ и
константы Фейгенбаума. Это генератор чисел, а не математика проекта.
Математика здесь — в **доказанных границах**: `sk_fix_mul` точен при любых
входах (16-битные лимбы), `sk_fix_div` требует `|b| < 2^30`, и это
записано в коде, а не подразумевается. Константы выводятся формулами
(Машин для π, ряд для e, Ньютон для √2) и проверяются в selftest.

## 1. Семь подсистем

```
core/    math      Q16.16, exp/tanh/sqrt, xoshiro, логистическая карта
         arena     5 бэкендов памяти, бюджеты, без фрагментации
         sched     кооперативные шаги, парковка, watchdog
         clock     Prime Clock, сверхпростые = чекпоинт + самопроверка
         vault     A/B слоты + WAL + CRC32C
model/   tensor    int8 + scale на строку, квантованный matmul
         moe       эксперты как блоки арены, router, LRU-evict
         jepa      encoder + predictor в латентном пространстве
learn/   train     онлайн-обучение, integer-friendly
         gen       генератор данных (facts→QA, арифметика, свой исходник)
agent/   think     цикл мыслей → план → действие → наблюдение
         tools     FS, sandbox-exec, без сети на DOS
evolve/  mutate    правка исходника, fitness-gate, выброс в source/gen_N/
rt/      dos/posix/win32   INT 21h/10h/16h, EMS/XMS, PC speaker, termios
```

Три вещи несут всю конструкцию: **арена с бюджетами** (OOM = деградация,
не падение), **кооперативный планировщик** (вкл/выкл задачи для
стабильности), **Prime Clock как единственное время** (воспроизводимость).

## 2. Инварианты

Нарушение любого — дефект архитектуры, а не баг.

**И1. Детерминизм.** Один и тот же вход даёт побитово тот же выход на
любом целевом железе. Следствие: никакой плавающей точки, никакого
`rand()`, никакой зависимости от RTC.

Этот инвариант однажды был нарушен не кодом, а **типом**. `sk_u32` был
объявлен как `unsigned long`, а на Linux x86-64 `long` — 64 бита. Все
64-битные сборки «проходили» тесты, потому что значения помещались, и
расхождение вылезло только на матвеке модели: результат отличался от
Windows-сборки в 55 раз.

Лечение в `sk_types.h`: тип выбирается по `<limits.h>` (`int`, если он
32-битный, иначе `long`) и проверяется **assert'ом времени компиляции**.
Новый компилятор, который сломает допущение, теперь падает на сборке, а
не в году 30.

**И2. Ограниченность памяти.** Ни одного `malloc` после инициализации.
Всё — из арены. Нехватка памяти возвращает `NULL`, а не вызывает abort.

**И3. Отсутствие потери состояния.** Состояние либо корректно, либо
отсутствует. Никогда — испорчено. Достигается двумя слотами и CRC.

**И4. Обратимость.** Любая операция, которую нельзя откатить, требует
явного разрешения. Проверяется тестом: случайная точка прогона должна
восстанавливаться из журнала побитово.

**И5. Мутационная поверхность.** Самоизменение ограничено явно
помеченными областями. Ядро (память, часы, чекпоинты, CRC) — immutable.

**И6. Деградация вместо отказа.** При нехватке ресурса система снижает
качество, но продолжает выполнять обязательный минимум.

## 3. Prime Clock

Единственный источник времени.

```
2, 3, 5, 7, 11, 13, ...        — последовательность
3, 5, 11, 17, 31, 41, 59, ...  — сверхпростые (A006450), точки чекпоинта
```

Реализация — сегментное решето Эратосфена: базовые простые до
65536 строятся один раз, каждый сегмент (4096 нечётных кандидатов)
вычёркивает свои составные. Память фиксирована (~25 КБ), что для DOS
критично: размер известен до того, как программа попросит память.

`sk_clock_seek(c, value, index)` продолжает ровно с того места — это
проверяется в selftest сравнением с непрерывным прогоном на 1000 шагов.

**Чего Prime Clock не делает.** Он не является доказательством
потраченного времени: цепочку можно промотать. Как защита от подделки
времени это не работает. Как монотонный номер версии без синхронизации
часов — работает (см. `docs/20-ideas.md`, И8).

## 4. Vault: почему сбой безопасен

Порядок записи, который делает сбой безвредным:

```
1. записать старый слот в STATE.TMP и вытолкнуть на устройство
2. атомарно заменить слот (POSIX rename / Windows MoveFileEx)
3. только потом обрезать журнал
```

Сбой до шага 2 оставляет целый слот нетронутым. Сбой после 2 оставляет
целый снапшот и журнал со старыми записями, которые replay пропускает.
**Нет окна, в котором оба слота плохие.**

Формат: `[magic][version][seq][len][payload_crc][header_crc][payload]`.
Все числа little-endian 32-битные, поэтому состояние, записанное на 8088,
читается на x86_64 и наоборот.

Оборванная запись в хвосте журнала — нормальное явление после kill.
Replay останавливается на первой некорректной записи и не считает это
ошибкой. Это проверяется в selftest.

### Цена устойчивости

Замер на обычном SSD:

```
write + fsync + close  : 84.9 мс
write + close          :  0.1 мс
```

Durability стоит в 850 раз дороже защищаемой работы. Поэтому политика
вынесена наружу явно:

- `SK_SYNC_NONE` — переживает убийство процесса (данные в кэше ОС);
- `SK_SYNC_DEVICE` — переживает пропадание питания.

Флаг `--durable` выбирает второе. По умолчанию первое, потому что
краш-тест измеряет именно его, а платить 85 мс на каждый чекпоинт ради
сценария, которого в тесте нет, — это трата 98% времени на защиту и 2%
на жизнь.

На DOS `fsync` отсутствует вовсе. Это задокументировано в `sk_io.c`, а не
замазано: после kill данные целы (они в кэше DOS), после пропадания
питания теряется последний снапшот. Именно поэтому резерв диска (И1 в
`docs/10-self-training.md`) на DOS критичнее, чем где-либо.

## 5. Арена и память

Bump-аллокатор с mark/release. Не `malloc`, потому что 50-летний прогон
не должен фрагментироваться.

```c
mark = sk_arena_mark(&a);
p = sk_arena_alloc(&a, n);     /* NULL при нехватке, не abort */
sk_arena_release(&a, mark);    /* вся фаза целиком */
```

Бэкенды: `OS` и `STATIC` готовы; `CONV`, `EMS`, `XMS`, `DPMI` — M1.
Интерфейс финальный, поэтому модельный слой пишется против него сразу.

Governor памяти в планировщике: при перерасходе паркуется задача с
наименьшим приоритетом, при появлении места — возвращается. Это и есть
«MoE для DOS» в части памяти: деградация качества вместо падения.

## 6. Вехи

| Веха | Выход | Критерий приёмки |
|---|---|---|
| **M0** | скелет, Prime Clock, Vault | selftest 38/38; 2.29 млн простых при 15 убийствах, 0 расхождений |
| **M1** | EMS paged store | 15 168 КБ доступно на DOS; round-trip через границы страниц |
| **M1b** | XMS, DPMI | плоское 32-битное адресное пространство |
| **M2** | модель, импорт TINY.BIN | воспроизведён baseline 61% на том же тесте |
| **M3** | MoE + прогрессивный формат | кривая «точность от байт» при 128K/512K/2M/8M |
| **M4** | тренер + гит для весов + канарейка | `skynet train f1 f2` → качество выросло, откат работает |
| **M5** | агент | цикл мыслей, инструменты, JEPA-голова |
| **M6** | эволюция | мутация → sandbox → регрессия → `source/gen_N/` или откат |

M0–M2 — недели, не годы. После M2 есть работающая вещь с числом, которое
можно показать.

---

## 7. Что осознанно не сделано в M0

- Модели, MoE, агента, эволюции — вехи M2+.
- DOS-бэкендов памяти — M1.
- `fsync` на DOS — его там нет (см. §4).
- Формата файла весов — M2, и он зависит от результата M3 (прогрессивный
  формат меняет раскладку).
